# Telemetry and outbound data (step 3a, issue #32)

Source: Orca code at `origin/autofactory` (upstream `80c9278b89` plus our docs), read on 2026-10-27.
Marking: **[read]** = read in the code. **[run]** = observed by running the app. **Nothing in this file is [run]**: the app was not started and no network monitor was used. Every "not verified" item has manual steps at the bottom.

## Headline

1. **[read]** Usage telemetry (PostHog) only transmits in builds where CI injected both `ORCA_BUILD_IDENTITY` and `ORCA_POSTHOG_WRITE_KEY` (`src/main/telemetry/client.ts` lines 25-38 and 63; `electron.vite.config.ts` lines 47-56). Any build made from source without those two variables gets `null` for both, and `initTelemetry` returns before creating a PostHog client. There is no runtime override. So **our dev build (`pnpm dev`) and any build we package ourselves cannot send telemetry** unless someone sets those variables at build time.
2. **[read]** The **released Orca installed on this PC is the real telemetry sender** (the official CI build has the key). Its switches: the environment variables `DO_NOT_TRACK` and `ORCA_TELEMETRY_DISABLED` (read at runtime, `src/main/telemetry/consent.ts` lines 76-83; only the values `1` or `true` count, `yes` or `0` do not), the Settings toggle (`optedIn=false`), and any CI variable.
3. **[read]** New profiles default to `optedIn: true` (comment in `src/shared/telemetry-settings-types.ts`), so on the installed copy the toggle is on until switched off.
4. **[read]** Crash reporting does **not** upload: `crashReporter.start({ uploadToServer: false })` in `src/main/crash-reporting/crashpad-capture.ts` line 51. Dumps stay on disk. No Sentry or similar library was found in `src/main`.
5. **[read]** No code change is needed for telemetry in the fork. The telemetry-off invariant is pinned by a test (below). No seam added.

## Manual steps for Kareem

1. PowerShell: `setx DO_NOT_TRACK 1` and `setx ORCA_TELEMETRY_DISABLED 1`. Fully quit every Orca process (check the tray and Task Manager) and relaunch; `setx` only affects new processes.
2. In the installed Orca: Settings > Privacy > turn off "Share anonymous usage data". Confirm the toggle shows disabled with the env-var reason.
3. Capture traffic with Wireshark or Fiddler, or Resource Monitor > Network (filter on the Orca processes), plus `ipconfig /displaydns` to map hosts. Start Orca, run an agent for 5 minutes, note every host. Repeat with `pnpm dev` (also `pnpm dev:fresh`).
4. Pass criteria: no `posthog.com` host in either session. The installed copy will still contact `github.com` and `onorca.dev` for updates unless blocked.
5. Check whether the dev build contacts `onorca.dev/plugins/kill-list.json` or `relay.onorca.dev` at idle (items 5 and 10).
